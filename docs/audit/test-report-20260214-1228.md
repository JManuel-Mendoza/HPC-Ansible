## Hallazgo principal (bloqueante)

Todas las ejecuciones remotas con `ansible`/`ansible-playbook` (conexión a hosts) fallaron en este entorno por:

> `ERROR! Unable to use multiprocessing, this is normally caused by lack of access to /dev/shm: [Errno 30] Read-only file system`

Evidencia:
- `tests/results/20260214-1228/canary/01_ping.log`
- `tests/results/20260214-1228/canary/03_converge_pass1.log`

Diagnóstico técnico:
- En este sandbox, `/dev/shm` está montado `ro` (read-only). Python multiprocessing que usa Ansible requiere `/dev/shm` escribible.

Evidencia local (referencial, no parte de la fase preflight):
- `mount | grep /dev/shm` mostró `tmpfs on /dev/shm ... (ro,...)`.

## Acciones sugeridas (para completar el E2E real)

Para poder ejecutar Fase 1 y Fase 2 (canary/full) se necesita correr las pruebas desde un entorno donde `/dev/shm` sea `rw` (normal en Linux) o desde un contenedor con `--shm-size` suficiente.

Re-ejecución recomendada (manual) en un control node “normal”:
1) Preflight:
```bash
ansible-inventory -i inventario.ini --graph --ask-vault-pass
ansible-playbook -i inventario.ini site.yml --syntax-check --ask-vault-pass
ansible-playbook -i inventario.ini site.yml --list-tasks --ask-vault-pass
```
2) Canary (master + 1 GPU worker si existe):
```bash
ansible -i inventario.ini 'master:worker1' -m ping --ask-vault-pass
ansible-playbook -i inventario.ini site.yml --limit 'master,worker1' --ask-vault-pass --skip-tags debug
ansible-playbook -i inventario.ini site.yml --limit 'master,worker1' --tags validate --ask-vault-pass --skip-tags debug
ansible-playbook -i inventario.ini site.yml --limit 'master,worker1' --tags validate_slurm --ask-vault-pass --skip-tags debug
ansible-playbook -i inventario.ini site.yml --limit 'worker1' --tags validate_cuda --ask-vault-pass --skip-tags debug
```
3) Full (solo si canary pasa): repetir convergencia + idempotencia + validaciones.

Nota de secretos:
- No ejecutar con `--diff` en etapas que puedan renderizar configs con passwords (por ejemplo `slurmdbd.conf`), a menos que se asegure sanitización de logs.
