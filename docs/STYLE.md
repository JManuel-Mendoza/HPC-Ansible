# Guía de estilo documental

1. La redacción debe mantenerse en tercera persona y tono semiformal.
2. Se evita el uso de primera persona (singular y plural) en toda la narración.
3. Se priorizan construcciones impersonales con `se`: `se recomienda`, `se valida`, `se debe`.
4. Las instrucciones se formulan en infinitivo o forma impersonal, sin tutear al lector.
5. El contenido técnico se conserva sin reinterpretaciones ni cambios de alcance.
6. No se modifican bloques de código, comandos, rutas, variables ni salidas esperadas.
7. Los nombres técnicos de roles, tags, playbooks y archivos se mantienen intactos.
8. Las listas deben ser breves, directas y orientadas a acciones verificables.
9. Las notas deben introducir contexto operativo; las advertencias deben indicar riesgo y condición.
10. En runbooks, cada validación debe incluir comando y criterio de resultado esperado.
11. Se recomienda mantener el orden de secciones existente, salvo correcciones menores de claridad.
12. Cuando se agregue terminología nueva, se debe usar de forma consistente en todo el documento.
